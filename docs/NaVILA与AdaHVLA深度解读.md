# 第一部分：NaVILA 深度解读

## 1.1 定位与基本信息

| 项     | 内容                                                               |
| ----- | ---------------------------------------------------------------- |
| 全名    | NaVILA: Legged Robot Vision-Language-Action Model for Navigation |
| 发表    | RSS 2025（Robotics: Science and Systems）                          |
| 作者    | An-Chieh Cheng、Yandong Ji、Zhaojing Yang 等（NVIDIA 团队为主）           |
| arXiv | 2412.04453（2024-12 提交，2025-02 修订 v2）                             |
| 官网    | navila-bot.github.io                                             |

**核心问题**：解决「腿足机器人的视觉-语言导航（VLN）」——让人用自然语言指挥四足机器人，把指令一路翻译到底层腿部关节动作。论文指出这一过程「非平凡（non-trivial）」，因为底层动作是高维连续的关节控制。

**核心解法**：两级框架（two-level framework），把 VLA 与 locomotion 技能统一起来，而非让 VLA 直接预测底层动作。

## 1.2 两级框架设计

| 层级            | 作用              | 输出                                           |
| ------------- | --------------- | -------------------------------------------- |
| 上层 VLA        | 看图像 + 听指令，做高层决策 | 生成带空间信息的中层动作，以**自然语言**表达，如「前进 75cm」「右转 30 度」 |
| 下层 locomotion | 接收语言指令，落地执行     | 精确的关节运动，并保证避障                                |

**两层连接方式**：

- VLA 输出一个**固定集合的可执行词汇**：`{move forward, turn left, turn right, stop}`
- 这些指令被转换为**固定命令速度**：
  - 前进：0.5 m/s
  - 左转：π/6 rad/s
  - 右转：-π/6 rad/s
  - 停止：0
- 再以对应时间持续执行，以对齐 VLA 输出的具体数值（距离/角度）

**双频率运行机制**：

- VLA 层：模型大、计算密集，以**较低频率**运行，提供高层导航指令
- locomotion 策略：**实时**运行，处理障碍物避让，提升鲁棒性

**框架的三个优势**（论文原文）：

1. **跨机器人泛化**：解耦低层执行后，同一 VLA 可替换低层策略应用于不同机器人（论文在 Unitree Go2、Unitree H1、Booster T1 上验证）
2. **语言域动作表示**：以中层语言表示动作，使 VLA 训练可利用多样化数据源（含真实人类视频、推理 QA），增强推理能力而不对特定低层命令过拟合
3. **双时间尺度**：locomotion 策略实时处理复杂避障

## 1.3 VLA 模型结构

**基础模型**：基于 **VILA**（NVIDIA 的视觉语言模型），选择基于**图像**的 VLM 而非视频编码器，原因是视频-文本数据缺乏限制了视频编码器预训练，且图像 VLM 泛化更强、知识更广。

**VILA 三部分**：

1. 视觉编码器（Vision Encoder）：图像 → 视觉 token
2. 投影器（Projector / MLP）：视觉 token 下采样并映射到语言域
3. LLM：自回归生成

**输入帧与 token 化**：

- 区分「历史帧」与「当前帧」：
  - 时间步 t 的图像 = 当前观测（用于即时决策，如路口右转、到达停止）
  - t 之前的帧 = 历史帧，作为记忆库（memory bank），追踪整体进度
- 采样策略：提取最近一帧作为当前观测；从之前 t-1 帧均匀采样历史帧，**第一帧始终包含**
- 帧数实验范围 8～64 帧
- 用文本提示区分两类帧（如 "a video of historical observations:" 与 "current observation:"），不引入特殊 token

**VILA 训练三阶段**（作为基础）：connector 对齐预训练 → 文本图像交织预训练 → 指令微调（全模块解冻）。

## 1.4 中层动作格式

**动作空间**（固定集合）：`move forward` / `turn left` / `turn right` / `stop`

**空间信息表达**：自然语言 + 数值参数，如「前进 75cm」「右转 30 度」。

**动作解析**：推理阶段用**正则表达式解析器**从 LLM 输出提取动作类型和参数。论文报告所有动作均被成功匹配映射。

**连续值标签生成**：训练时鼓励 LLM 生成连续值标签；合并连续动作（最多 3 个，如两个「前进 25cm」合并为「前进 50cm」），减少数据量、增加动作多样性、缓解过拟合。

## 1.5 下层 locomotion 策略

**平台**：Unitree Go2，18 DoF（底座 6 + 每腿 3×4），训练时仅控制 12 个腿关节。

**传感器**：LiDAR（Unitree L1），安装在头部底座，15Hz 广播点云。选 LiDAR 的原因是它**能检测透明物体、强光下鲁棒**。

**动作/观测空间**：

- 动作：期望关节位置 q^d ∈ R^12，经刚度和阻尼转为扭矩
- Critic 观测（特权信息，仅训练）：本体感觉 + 速度指令 + 特权地形高度扫描
- Actor 观测（仅真机可用）：排除线速度（真机不可用），用本体感觉历史隐式推断；经 LiDAR 高度图感知地形

**高度图构建**（LiDAR → Height Map，Table XII 参数）：

- 视场 360°×90°，水平分辨率 4°，体素 0.06m，X 范围 [-0.8, 0.2]m，Y 范围 [-0.8, 0.8]m，Z 范围 [0.05, 0.5]m
- 每个体素取范围内最低值，再对最近 5 帧点云做最大滤波平滑

**训练算法**：PPO，**单阶段训练**（区别于常见两阶段 teacher-student），消除策略蒸馏，直接与环境交互；RTX 4090 上超 60K FPS。

**奖励函数**（Table X，部分）：线速度跟踪、角速度跟踪、z 方向线速度惩罚、关节加速度惩罚、能量惩罚、身体高度、足部滑动等。

**避障机制**：高度图让策略能检测障碍物（含透明玻璃），即使高层 VLA 没检测到，locomotion 策略也能自主避让。

## 1.6 训练数据与流程

**SFT 数据混合（四来源）**：

1. **真实视频导航数据（Human Videos）**：2K 段 YouTube egocentric touring 视频，entropy-based sampling 处理成 20K 条轨迹，用 MASt3R 估计相机姿态提取逐步动作，VLM captioning + LLM rephrasing 生成指令。论文称这是「首个展示直接在人类视频上训练可改善连续环境导航」的工作。
2. **模拟导航数据**：VLN-CE 的 R2R-CE、RxR-CE，Habitat 中用 shortest path follower 生成动作序列，含 stop 动作标签重平衡。
3. **辅助导航数据**：EnvDrop 增强指令、导航轨迹摘要任务、ScanQA（真实 3D 扫描 QA，增强空间理解）。
4. **通用 VQA 数据**：保持一般能力，防灾难性遗忘。

**训练流程**：起点是 VILA 阶段二模型，SFT 数据混合微调整个 VLM 一个 epoch，三组件全解冻，学习率 1e-4、cosine decay、warm-up 0.03。最终视觉指令调优在 4 个 A100 节点（每节点 8 GPU）上 18 小时。推理单张 RTX 4090 约 1 FPS。

## 1.7 实验结果

**VLN-CE 基准（Table I，仅单视角 RGB）**：

- R2R-CE Val-Unseen：SR 54.0，SPL 49.0
- RxR-CE Val-Unseen：SR 49.3，SPL 44.0
- 对比 NaVid（此前单视角 SOTA）：R2R SR 37.0 → 54.0（+17 点）

**跨数据集零样本（Table II，仅训 R2R 测 RxR）**：SR 34.3 vs NaVid 23.8（+10.5 点）。

**ScanQA（Table III）**：64 帧时 Cider 102.7，超过所有 3D LMM（这些模型需 3D 扫描或 RGBD + 相机姿态）。

**低层策略（Table V）**：线速度误差 0.066、角速度误差 0.113、碰撞率 0.81（对比 ROA 分别为 0.161、0.152、3.09）。

**VLN-CE-Isaac 基准（Table IV）**：Go2 上 NaVILA-Vision SR 50.2 vs Blind 36.2（+14 点）；H1 上 Vision 45.3 vs Blind 24.4（+21 点）。

**真实世界（Table VI）**：Go2 上 25 条指令 88% 成功率，复杂指令 75%；对比 GPT-4o 显著领先。同一 VLA 模型不做重训直接迁移到 Booster T1 人形机器人。

**消融**：无标签重平衡 SR 49.7→30.0；含人类视频 SR 49.7→54.0（+4~5 点）；8 帧已足够，更多帧增益有限。

**量化（Table XIII）**：W4A16（AWQ）延迟 594.58ms→367.80ms（-40%），显存 18.5GB→8.6GB，SR 49.7→48.2。

## 1.8 失败案例与局限性

**明确记录的失败（Fig. 13）**：机器人正确遵循指令，但发生偏差时**无法有效纠错**，最终未到卧室。改进方向：更大规模真实模拟训练 + 引入显式推理数据。

**局限性**：

1. 泛化与空间理解待提升，部分真实场景仍失败
2. 计算密集（约 1 FPS），量化可缓解
3. 图像传输开销大（VLA 跑在外部 GPU），机载部署是未来方向
4. 模拟到现实有差距：不用 Oracle 低层策略时 Go2 成功率降 15%、H1 降 27%

# 第二部分：AdaHVLA 深度解读

## 2.1 定位与基本信息

| 项     | 内容                                                                                 |
| ----- | ---------------------------------------------------------------------------------- |
| 全名    | AdaHVLA: Adaptive Harnesses for Long-Horizon Vision-Language-Action Execution      |
| 作者    | Junyi Tang、Jie Peng、Zezhen Ding、Yuan Shen、Tianlong Chen（UNC / USTC / HKUST / CUHK） |
| arXiv | 2609.29204（cs.RO）                                                                  |
| 仓库    | github.com/Haaareally/AdaHVLA-Adaptive_Harness_VLA                                 |

**核心主张**：VLA 模型局部控制与指令跟随能力强，但在需持续记忆与规划的 long-horizon 任务中不足。AdaHVLA 在 VLA 之上叠加一层**可编辑的代码协调层（harness）**，用机器人执行经验自动精炼这层协调代码，把「任务级推理 + 记忆」和「VLA 局部执行」粘合起来。

**本质特征**：**不改 VLA 参数、只改协调代码**。

## 2.2 问题形式化

**任务实例** ξ = (x, ℰ, s₀)：

- x：指令（instruction）
- ℰ：环境（environment）
- s₀：初始机器人与场景状态

**决策边界 t 的协调**：

```
(q_t, κ_t, m_{t+1}, z_t) ~ H_c(· | ℋ_t, m_t)
a_t ~ π_θ(· | q_t, κ_t)
```

| 符号  | 含义                                    |
| --- | ------------------------------------- |
| H_c | 由源码修订 c + 推理智能体调用诱导出的策略               |
| q_t | VLA instruction（指令）：执行器该处理什么目标        |
| κ_t | observation context（观测上下文）：执行器接收什么上下文 |
| m_t | runtime state（运行时状态）                  |
| z_t | termination flag（终止标志）∈ {0,1}         |
| a_t | VLA 指令或动作序列                           |
| ℋ_t | 交互历史 = (x, o\_{≤t}, a\_{<t})          |

**优化目标**：max_c E[R(τ; ξ)]，在候选修订集 𝒞 里最大化期望成功率，VLA 参数 θ 与机器人配置冻结。

## 2.3 harness 的四大协调职责

> 说明：论文正文以「功能职责」描述，GitHub 仓库 `harness.py` 中对应有 ContextPolicy / ProgressPolicy / HandoffPolicy 等类名，二者是同一件事的两种表述。

### （1）任务进度与引导（Task progress and guidance）

- 有序子任务与目标定义可观测的进度标准
- 决定何时推进活跃目标、q_t 给原始指令还是局部目标
- 推进依据「先前动作留下的状态」（如新目标条件是否建立）

### （2）上下文与视觉刷新（Context and visual refresh）

- 为推理智能体挑选观测、进度记录、持续纠正
- 控制执行器接口的视觉刷新时机
- 关键洞察：**「转弯后的早期视觉缓冲对路线推理仍有用，但对局部执行已过时」**——历史观测保留规则不能一刀切

### （3）恢复（Recovery）

- 决定纠正性引导何时开始、持续、结束
- 实例：从「纠正性转弯」持续到「通过预期门洞的前向运动」

### （4）完成（Completion）

- 完成检查基于剩余目标，局部停止信号不必终止整个任务

**贯穿原则**：修订改变的是这些决策「如何跨 VLA 调用相互作用」，而非 VLA 动作模型；固定源码 ≠ 固定指令序列。

## 2.4 多智能体适应流程

**核心设计原则**：三个 agent 用各自独立的工作上下文，靠结构化记录交换信息，而非共享对话。-

### Analysis Agent（证据分析）

- 输入：每次 rollout 的相机观测、日志、轨迹段，**按 request ID 对齐**并链接到源码修订
- 产出：可测试协调假设
- 操作原则：**把观察到的事件与解释分开记录**

### Revision Agent（修订）

- 输入：源代码 + 相关尝试
- 产出：代码补丁 c′ = c ⊕ Δ
- 约束：补丁背后的假设与预测效果须在 rollout 前记录；须通过独立的源码与接口审查

### Behavioral Assessment Agent（行为评估）

- 输入：同一任务实例上父版本 vs 修订版本 rollout，在全新上下文比较
- 产出：三个分开的评估——目标效果、整体行为、最终成功
- 动机：任务结果同时取决于感知与控制，会掩盖代码修订的贡献，所以不能只看任务成功

## 2.5 可测试协调假设（Testable Coordination Hypothesis）

每条假设包含四部分：

| 组成    | 原文                   | 含义                |
| ----- | -------------------- | ----------------- |
| 可疑机制  | suspected mechanism  | 被怀疑导致问题的协调机制      |
| 支持证据  | supporting evidence  | 支持该假设的观测          |
| 预期效果  | expected effect      | 修改后预期的行为变化        |
| 可观测指标 | observable indicator | 下次 rollout 可验证的指标 |

## 2.6 归因门（Attribution Gate）

设：

- û：修改的机制是否被触发（1/0/不确定）
- v̂：轨迹在触发前是否已发散（1/0/不确定）

```
χ = 1{ û = 1 ∧ v̂ = 0 }
```

**含义**：χ = 1 当且仅当「机制确实被触发」且「触发前轨迹未发散」。

**作用**：

- χ = 1 时，比较才能更新假设支持度：目标改进 → 增强支持；效果不变/退化 → 削弱支持
- χ ≠ 1 时，支持度保留，但结果仍可用于后续精炼

**道理**：不能因单次成功就归功于某次改动——须先确认「改的东西真触发了、且不是碰巧早就跑对」。可重复性需更多 rollout，而非单次成功 episode 推断。

## 2.7 修订图（Revision Graph）

图 𝒢 连接四类节点：

1. 代码版本（code versions）
2. 假设（hypotheses）
3. Rollout 证据（rollout evidence）
4. 行为评估（behavioral assessments）

**为什么用图而非只追最新版本**：只追最新修订会把未解决的协调问题与后续改动纠缠，导致重复无用尝试；图结构让相关尝试跨分支保持可检索。

**容量参数**：

- W：最大活跃候选叶节点数
- D：当前任务焦点内最大修订深度

**候选排序**：先任务成功率，再目标行为效果、整体行为效果。

**区分**：「扩展候选」的决策 ≠ 「更新假设支持度」——未完成任务仍可为进一步精炼提供方向。

## 2.8 跨任务适应记忆

原则：把相关 agent 上下文压缩进长期适应记忆。

**保留六类**：协调问题、已测试假设、已尝试变更、观测到的效果、评估条件、指向支持证据的链接。

**跨任务切换规则**：

- 选定 harness + 保留的 agent 上下文持续存在
- 检索摘要引导新假设新修订
- 重置：运行时状态、局部探索深度
- 无关任务的修订上下文重建；每次行为评估从头开始

**本质**：代码保留「已适应的协调策略」，记忆保留「在新任务/环境下继续精炼所需的证据与未解问题」。

## 2.9 执行阶段数据流

```
Harness 维护 m_t → 构建推理上下文 → 推理智能体产生决策
      ↓
决定 q_t（原始指令 or 局部目标）+ κ_t（观测上下文）
      ↓
VLA π_θ 接收 (q_t, κ_t) → 产出 a_t
      ↓
Controller 执行 → 产生 o_t
      ↓
Harness 更新 m_{t+1}，判断 z_t（是否终止）
```

每次的 request ID（R_i）用于把观测、日志、轨迹段对齐回对应源码修订。

## 2.10 实验结果

**导航（NaVILA-LH，Table I）**：Single VLA 2.5% → Initial Harness 22.5% → 适应后最高 57.5%（GPT-5.6-sol Max）。6 种适应模型间差距达 25.8 点。

**操作（Table II）**：π₀.₅ 在 L1 增益最大 +30.8 点（25.0%→55.8%）；L2 最高 +28.3 点。性能与参数量非单调（π₀.₅ 3.3B 优于 OpenVLA-OFT 7.5B）。

**消融（关键）**：

- 去掉完成检查：导航 57.5%→29.2%
- 去掉上下文（紧凑记忆）：导航 33.3%
- 去掉恢复：L2 操作 38.3%→23.3%
- 去掉修订图（平坦历史）：导航 42.5%
- 仅成功率选择：导航 38.3%

**真实世界**：Go2 在 R59 偏离后，纠正性引导 R67–R72 持续到 R75 达成 Goal 2，全程无需重启。

## 2.11 局限性与未来工作

**局限**：

1. 适应增益依赖适应模型（LLM）能力，差距达 25.8 点
2. 基础模型视觉/空间推理错误会同时影响修订与评估，解耦上下文无法消除共享基础模型的系统性错误
3. 各协调机制价值随任务复杂度变化，无法统一预设
4. L1/L2 的工作流长度与阶段依赖同时变化，无法单独归因

**未来工作**：人机协同适应、扩展到 VLA 参数微调（用持久记忆识别反复失败模式，选择经验用于 fine-tuning 或 RL 后训练）。

# 第三部分：两者关系与对本项目的意义

## 3.1 两者关系

```
NaVILA（执行/避障能力） → AdaHVLA（协调能力，建立在 NaVILA 之上） → 本项目（借鉴思想）
```

- NaVILA 是 AdaHVLA 的**执行底座**（AdaHVLA 示例 harness 用 NaVILA 做局部导航，NaVILA-LH 基准从 NaVILA-Bench 构建）
- AdaHVLA 的「导航 2.5%→57.5%」提升，是在 NaVILA 之上**加协调层**实现的，而非替换执行器
- 两者是**上下游关系**，不是替代关系

## 3.2 三系统层级对照

| 层      | NaVILA                       | AdaHVLA                   | 本项目 Safety_Agent                  |
| ------ | ---------------------------- | ------------------------- | --------------------------------- |
| 决策/协调层 | 上层 VLA（VILA/Llama3-8B），直接产动作 | Adaptive Harness（可编辑协调代码） | 大脑层（patrol.py/ui.py），写死路线与提问      |
| 执行层    | 下层视觉运动 RL 策略（避障）             | 复用 NaVILA，VLA 参数冻结        | 手脚层（client.py + WSL DDS 直控，开环无避障） |

## 3.3 本项目的两个明确缺口

| 现状               | 缺什么         | 对应谁             |
| ---------------- | ----------- | --------------- |
| 「速度×时间」开环走位，无避障  | 底层避障执行      | NaVILA 下层 RL 策略 |
| 走位失败/站不起来就终止，无恢复 | 进度追踪 + 失败恢复 | AdaHVLA 恢复机制    |

## 3.4 借鉴价值评估（事实 + 判断）

**事实层面**：

1. NaVILA 与 AdaHVLA 的机器人平台均为 Unitree Go2，与本项目一致
2. 本项目巡检属于 long-horizon 视觉-语言-动作任务，正是 AdaHVLA 的目标场景
3. 本项目已是「大脑层→手脚层」分层结构，与 AdaHVLA 的 harness→VLA 映射同构

**判断层面（需验证）**：

1. 最大价值在「协调层可适应」思想：把写死的巡检路线/诊断策略变成可自动修订的代码，而非现场人工标定


2. 「完成检查 + 恢复机制」两个消融项最值得借鉴：本项目纯开环、无失败恢复，是明显短板
3. 落地方式：不替换已跑通的 DDS 直控，而是把 harness + 多智能体修订思想吸收进 patrol.py 编排层

**约束（事实）**：

1. AdaHVLA 完整复现需 Isaac Sim 4.1.0 + NVIDIA GPU + 两套 Python 环境 + 视觉推理 API，依赖重；其「真实世界部署部分」在仓库中标注 coming soon
2. AdaHVLA 默认执行器是 NaVILA，与本项目 DDS 直控不同，直接移植不可行，借鉴协调层思想才可行
3. NaVILA 训练成本极高（VILA 大模型 + 多模态导航数据 + Habitat/Isaac 仿真），与轻量架构差异大，不宜照搬

## 3.5 结论

- **协调层**（抄 AdaHVLA）：轻量可行，是短期可落地方向
- **执行层避障**（抄 NaVILA）：重且难，是长期方向
- 建议优先借鉴 AdaHVLA 的「进度追踪 + 失败恢复 + 协调层可适应」思想，落地到现有 patrol.py，保留 DDS 直控不变
