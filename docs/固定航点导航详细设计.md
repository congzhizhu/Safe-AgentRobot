# 固定航点导航详细设计

> 本文档为 Safety_Agent 机器狗端「固定航点导航」能力的设计方案。
> 目标读者：项目开发者。状态：已实现并真机验证（`src/robot/navigator.py`），控制参数仍需真机标定。

---

## 1. 目标与范围

在现有「大脑层（patrol.py）→ 手脚层（client.py + robot_service.py）」架构上，新增一个**闭环导航**能力，使机器狗能够按预设的固定航点序列自主移动到目标点，到位后交接给现有的隐患诊断逻辑。

本方案将现有 `patrol.py` 中「速度 × 时间」的**开环**走位，升级为「位置反馈 → 朝向纠偏 → 距离判定」的**闭环**导航。

### 明确不做的事（本期范围外）

- 不做地图构建（SLAM / 点云建图）。
- 不做全局路径规划（A* 等）。
- 不做主动避障算法（依赖 Go2 内置 LiDAR 避障能力，见第 5 节）。
- 不做坐标标定映射（起点标定采用「点开始那一刻」的狗位姿作为任务原点，见 6 节坐标系说明）。

## 2. 关键事实与前提

### 2.1 定位能力来源

Go2 通过 `unitree_sdk2py` 订阅 `rt/sportmodestate`（低频为 `lf/sportmodestate`）话题，可获得**世界坐标系下的位置 `(x, y, z)` 与姿态 RPY（含偏航角 yaw）**。

- 来源：宇树官方文档中心《Go2 SDK 开发指南》及 SDK 示例 `read_highstate.py`。
- 坐标特性：该位置为**上电时初始化的相对世界坐标系**，原点为开机时狗的位置，x 轴正方向为开机时前进方向。
- **局限**：这是惯性/足端里程计性质的相对定位，长时间、长距离行走后会累积漂移。漂移量受地面摩擦、打滑影响，无法从文档精确量化，属腿式机器人里程计的共同已知局限。

### 2.2 避障能力来源

- Go2 全系标配 4D LiDAR L2（360°×96°），「探物避障」为内置功能。
- 在高级运动模式下，`Move` 指令会由狗的固件结合 LiDAR 做自主避障（减速/绕行）。
- `sportmodestate` 消息中包含四方向障碍距离字段（前/后/左/右），但该字段的可用性依赖**固件版本与运动模式**，需真机实测确认。

### 2.3 现有代码能力盘点

| 能力 | 现状 | 所在 |
|------|------|------|
| 速度控制 | 已有（`/move`，10Hz 重发，限幅） | `robot_service.py` |
| 原地转向 | 已有（`vyaw` 限幅 ±1.2 rad/s） | `robot_service.py` |
| 拍照 | 已有（`/capture`） | `robot_service.py` |
| 急停 | 已有（`/estop`） | `robot_service.py` |
| **位置/偏航反馈** | **缺失** | 需新增订阅 |

**结论**：导航的缺口不在控制算法，而在「执行层缺少位置反馈订阅」。需改动两个文件，约 40～60 行新增代码。

```
│  新增：订阅 rt/sportmodestate，暴露 GET /pose               │
└─────────────────────┬────────────────────────────────────┘
                      │  unitree_sdk2py + CycloneDDS
┌─────────────────────▼────────────────────────────────────┐
│  Go2 机器狗（内置 4D LiDAR 避障）                            │

```

### 3.2 数据流（单航点）

```
navigator.py                         robot_service.py
    │                                       │
    │  GET /pose                            │
    ├──────────────────────────────────────►│  读取最新 sportmodestate
    │◄──────── (x, y, yaw) ─────────────────┤
    │                                       │
    │  计算朝向误差 delta = theta_d - yaw    │
    │  if |delta| > 阈值:                    │
    │    POST /move {vyaw}                  │
    ├──────────────────────────────────────►│  Move(0,0,vyaw) 10Hz
    │  else:                                │
    │    POST /move {vx} (短时长)            │
    ├──────────────────────────────────────►│  Move(vx,0,0) 10Hz
    │                                       │
    │  计算距离 dist                         │
    │  if dist < 到达半径: 航点完成            │
    └───────────────────────────────────────┘
```

## 4. 控制律：纯追踪（Pure Pursuit）

对每个航点执行以下循环，直至到达或超时：

1. 读取当前位置 `(x, y)` 与偏航 `yaw`。
2. 计算目标向量与期望朝向：

   ```
   dx = target_x - x
   dy = target_y - y
   theta_d = atan2(dy, dx)
   delta = normalize_angle(theta_d - yaw)
   dist = sqrt(dx^2 + dy^2)
   ```

3. **朝向纠偏**：若 `|delta| > 朝向阈值（默认 8°）`，以 `vyaw = clamp(k_yaw * delta)` 做原地转向。
4. **前进**：朝向对齐后，以 `vx = min(v_max, k_lin * dist)` 前进一小段时间（默认 0.5 s）。
5. **到达判定**：`dist < 到达半径（默认 0.15 m）` → 航点完成。
6. **超时保护**：单航点累计尝试超过 `max_steps`（默认 200 步）或 `max_time`（默认 60 s）未到达，则标记失败并记录，避免死循环。

### 参数表（建议默认值，需真机标定）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 朝向阈值 | 8° | 小于此值视为已对准 |
| 转向增益 k_yaw | 0.5 | 角速度 = k_yaw × delta，经 1.2 rad/s 限幅 |
| 线速度上限 v_max | 0.3 m/s | 低于硬件上限 0.6，留安全余量 |
| 线速增益 k_lin | 0.5 | 接近目标时减速 |
| 前进步长 | 0.5 s | 单次前进指令时长 |
| 到达半径 | 0.15 m | 判定到达的距离阈值 |
| 单航点最大步数 | 200 | 防死循环 |
| 单航点超时 | 60 s | 防死循环 |

> 注意：以上数值为经验初值，**必须在真机上标定**，尤其是朝向阈值与转向增益，直接决定导航是否震荡。

## 5. 避障策略（依赖狗自身能力）

### 5.1 主避障：Go2 内置 LiDAR

Go2 在高级运动模式下，`Move` 指令会由固件结合 LiDAR 自主避障。**导航代码不应自行计算避障**，只需正常下发前进指令即可，遇到障碍时狗会减速或绕行。

- 前提：狗需处于可避障的运动模式（advanced / ai 模式）。
- 风险：内置避障的绕行会导致狗偏离直线航向，从而与纯追踪的「朝向纠偏」产生交互。需在真机验证：若绕行导致航点偏离过大，应放宽朝向阈值或缩短前进步长。

### 5.2 软件兜底：障碍距离急停（可选，二期）

若真机确认 `sportmodestate` 的障碍距离字段可用，可增加一条保守规则：

```
if 前方障碍距离 < 安全距离(0.3m):
    estop()   # 保守急停
```

该规则作为二次保险，避免依赖内置避障的单一失效点。

## 6. 航点配置

航点列表写入配置文件 `configs/nav_waypoints.yaml`，示例：

```yaml
# 相对「点开始航点导航那一刻」狗位姿的偏移量（单位：米）
arrival_radius: 0.2         # 到达半径
heading_threshold_deg: 18.0 # 朝向对准死区
waypoints:
  - name: "A区入口"
    x: 2.0
    y: 0.0
  - name: "B区配电箱"
    x: 4.5
    y: 1.2
  - name: "C区消防栓"
    x: 3.0
    y: 3.0
```

### 坐标系说明

航点为**相对「点开始航点导航那一刻」狗位姿**的偏移量（即任务原点，非上电原点）。每次点开始导航，导航器会调用 `_calibrate()` 把当前位姿标定为原点，因此无需把狗摆回上电位置。

- 原点 = 开始导航时狗所在位置；x 轴正方向 = 开始导航时狗前进方向。
- 航点 `(x, y)` 含义：沿当前朝向直走 `x` 米，再向左偏移 `y` 米（`y` 为负则右偏）。

> 局限：原点基于惯性/足端里程计定位，长时间、长距离行走后会累积漂移，因此任务应尽量在较短距离内完成。

## 7. 与隐患排查的衔接

用户已确定「航点即巡检点」：每个航点到达后，自动执行一次拍照 + 隐患诊断。

衔接流程：

```
for 每个航点:
    navigate_to(航点)           # navigator.py 闭环导航
    if 到达成功:
        frame = capture()        # 复用 client.capture
        result = diagnose(frame) # 复用现有隐患诊断逻辑（agent）
        记录 result
    else:
        记录该航点导航失败，继续下一航点
生成巡检报告                    # 复用现有报告生成
```

`patrol.py` 的改动方式：将现有「固定走位序列」替换为「调用 navigator 到达航点」，诊断与报告逻辑保持不变。

## 9. 风险与未知项

1. **定位漂移**：相对里程计定位会随行走累计漂移，长距离/多次转向后误差增大，可能导致航点判定偏差。缓解：缩短航点间距、定期回到已知点校准（二期）。
2. **避障与航向纠偏的交互**：内置 LiDAR 绕行可能使狗偏离直线，与纯追踪纠偏产生震荡。需真机调参（朝向阈值、步长）。
3. **`sportmodestate` 障碍字段可用性未知**：依赖固件版本与运动模式，需真机实测确认后才能做软件兜底急停。
4. **参数需真机标定**：所有控制参数为经验初值，必须在真机验证后定值。

## 10. 事实与推测的区分

**可验证事实**：
- Go2 可通过 `sportmodestate` 订阅世界坐标位置与 yaw（宇树官方文档 + SDK 示例）。
- Go2 全系标配 4D LiDAR L2，探物避障为内置功能（宇树官方产品参数页）。
- 现有 `robot_service.py` 仅有 SportClient / VideoClient，未订阅位置状态（源码直接可读）。
- 现有 `client.py` 仅有 move/act/capture/estop，无位置查询接口（源码直接可读）。

**个人推测 / 需真机验证**：
- 控制参数（朝向阈值、转向增益、到达半径等）的取值需真机标定，本文默认值为经验初值。
- `sportmodestate` 障碍距离字段的可用性需真机实测。
- 内置避障绕行与纯追踪纠偏的交互行为需真机验证。
